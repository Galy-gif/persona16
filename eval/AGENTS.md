# Eval Agent 约定

本文件适用于 `eval/**`，并继承仓库根 `AGENTS.md`。

## 评测原则

- Eval 负责验证产品声明，不负责绕过 Engine/Web 的正式执行路径。尽量复用生产 Prompt、Runtime 契约和最终交付门。
- 硬门先于软评分：任一场景语义硬门失败都不能被总体均分覆盖。
- 区分“最终交付是否通过”与“模型首答健康度”；重试或兜底后的正确交付不能被记成原始模型成功。
- 自动 Judge 只做形成性批量评估，不能替代隐藏来源的人工盲审。没有真实付费运行或人工证据时，不宣称发布门已通过。
- 每次可比较结果必须绑定代码 SHA、Prompt/协议版本、模型、参数、语料版本、样本数和运行时间。

## 语料与产物

- `corpora/registry.json` 是语料注册入口；新增/修改语料时同步 registry、校验器和相关测试。
- 金标准必须来自可审计的原创校准或人工评审，不能把模型即时生成内容直接当作真值。
- `eval/artifacts/` 中的运行结果是生成物；不要手改汇总来改变结论，也不要把含敏感输入的临时 artifact 提交到仓库。
- 报告必须从逐条结果重算，不信任可单独编辑的汇总字段。

## 验证

- 类型检查：`pnpm --filter @persona16/eval typecheck`。
- Eval 与全仓单元测试：`pnpm --filter @persona16/eval unit`（等价于根目录 `pnpm test`）。
- 只运行与变更对应的协议；任何会调用真实模型的命令，先确认所需环境变量、预计样本量和费用边界。
- 修改报告聚合逻辑后，用小型 fixture 验证失败、跳过、重试恢复和兜底路径。
