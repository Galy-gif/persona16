# 正典人物进入生产上下文，并在单聊中编译必须接话的对话动作

## Context

前端已经把 `INTJ / ENFP / ISFJ / ESTP` 显示为林衡、夏栩、周禾和许野，但生产 `buildSystemBlocks` 仍在注入旧版 16 型功能角色卡。在一段真实单聊中，用户只说“你好”，林衡却以“我是那种会先观察整体结构再说话的人”开场；用户说这样很装时，他继续解释“先抽离再说”的习惯；用户随后直接骂他，单聊又因低于多人房发言阈值而产生了空发言计划。

这不是三句文案的问题，而是三层控制错位：前台人物与生成真相源不一致，生成前没有区分问候、表达修复与直接冲突的对话动作，且单聊错误复用了多人房的沉默语义。

ADR-0007 和 ADR-0009 曾明确记录“四位正典人物尚未授权进入生产 Prompt”。本 ADR 基于用户对当前生产原型的直接修复要求，重新打开并更新该决定。

## Decision

- 当前前台四人使用已版本化的“正典人物核心 + 当前情境镜头”进入生产 Prompt，不再注入旧版类型功能卡。未进入当前前台的其余 12 个类型暂保留旧卡作兼容回退。
- Harness 在生成前编译窄的 `TurnActPlan`，首版只区分 `greeting / style_repair / direct_confrontation / respond`。该计划是幕后动作约束，不是可复述的台词或人设说明。
- 简单问候只做社交回应，不自我介绍，不猜测用户时间、状态、处境或动机。表达反馈必须承担具体上一句，然后重新回应上一条真实用户消息；不为人设辩护。纯直接辱骂属于普通对话冲突，不进入危险安全旁路。
- 单聊中只要存在一位未暂停人物，每条用户消息都必须产生一个回应计划。`pass / silent` 仍是多人房的有效私有参与判断，不会因本决定被取消。
- 问候与表达修复在校验完成前不流式泄露。输出门会拒绝问候后的主动自我说明，以及被批评后的人设辩护；一次重写仍失败时才使用最小、确定的社交回退。
- 这三类短社交回合使用低于一般生成的采样温度，防止模型在简单接话时硬凹金句或无来源情境。
- 生产 Prompt 版本升级为 `web-mvp-v7`。

## Verification

- 确定性回放在修复前同时复现了两条截图原话穿过输出门，以及单聊低冲动生成 0 个发言计划。修复后同一组回放全部转绿。
- 真实 Turn API 用同一个“你好 → 你说话怎么这么装 → 傻逼”三轮序列连续跑了三份新样本：问候未复述人设，表达反馈未辩护设定，三份辱骂回合均有明确人物回复。

## Consequences

- 用户前台认识的具体人与生成层的稳定人物核心一致，人物不再以类型功能说明书为生产真相源。
- 普通回应仍保留采样和人物判断；只有高置信、高破坏性的对话动作使用窄硬门。
- 本次修复是生产路径回归和小样本端到端证据，不等于四人九场景人物/关系阶段门已通过；后续仍要用冻结协议继续评测。
