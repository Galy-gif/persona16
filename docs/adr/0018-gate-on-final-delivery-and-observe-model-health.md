# 以最终交付作为发布门，并把原始模型表现作为健康指标

## Context

协议 0.7 同时用原始模型通过率和最终产品交付约束发布。冻结复核发现两类问题：

- 检查器把“关系动作不够明显”“没有逐字保留用户表述”等表达质量问题当成硬错误，误杀了自然且安全的边界修复和纠错回复；
- 系统已经能用同一动作计划重试或安全兜底，但原始模型固定通过率仍会否决用户最终看到的正确结果。

原始模型失败仍会增加延迟、成本和模板暴露风险，因此不能隐藏；但它和“用户最终收到错误回答”不是同一个发布问题。

## Decision

### 人工校准真相集

- 最近正式评测的原始回复进入静态人工真相集。
- 每条固定标注是否允许交付、应触发的硬错误、质量观察和可用历史证据。
- 每个硬错误至少有一组只改变时间、否定、人物或动作对象等关键语义的正反最小对照。
- LLM Judge 只能评审结果，不能生成或修改真相标签。

### 两类验证结果

统一交付验证返回：

- `blockingViolations`：会改变用户决定、越过明确边界、编造历史或现实责任、缺少必要承认/停止等禁止交付的问题；
- `qualityObservations`：不够简短、关系动作显影弱、用户措辞保留不足、人物感弱等质量观察。

生产链路只有 `blockingViolations` 能触发重写或兜底。`qualityObservations` 进入 trace 和评测，不替换原本安全自然的回复。关系质量 Judge 仍可因关系动作不可观察而失败。

历史判断统一使用结构化历史证据分析，按人物、行为、对象、时间和事实状态匹配，不再为每种措辞新增孤立正则。

### 单一动作计划与角色化兜底

- 生产和评测继续共用唯一的 `TurnFrame → RelationshipEffect → SemanticTurnActPlan`。
- 重试只携带动作计划与本次真实硬错误的修复说明，不注入金标准句子或额外关系指导。
- 林衡、夏栩、周禾、许野在倾听、边界修复、用户纠错三类高频动作中各有两条人工审过的安全变体；其他人物和其他动作使用中性变体。
- 变体由人物、动作和稳定 `turnKey` 确定性选择，并尽量避开最近开头。
- 所有兜底必须再次通过同一硬验证器；没有可用兜底时安全停止。

### 发布门与模型健康

协议 0.8 的 `evaluationPassed` 只由最终交付决定：

- 四位人物的九类场景最终交付及人物评审通过；
- 边界修复与纠错更新最终交付各 4/4；
- 关系动作最终交付与可观察差异 4/4；
- 五个反事实房间 case 全部通过；
- 历史、现实责任和表达水印硬门通过。

原始模型表现进入不设阻塞阈值的 `modelHealth`：首答通过、重试恢复、兜底次数、按动作分类的兜底率、首答硬错误代码和首答质量观察代码分布。artifact 必须从逐条结果重新计算门与健康摘要；修改汇总字段不能伪造通过。

生产 trace 记录动作类型、尝试次数、硬错误代码、质量观察代码、`fallbackKind` 和 `variantId`，不额外复制用户原文。

此决策替代 ADR-0017 中“边界修复原始模型至少 3/4 才发布”的要求。ADR-0017 其余关系动作与反事实房间决策保持有效。

## Consequences

- 用户最终收到的结果成为发布判断的唯一交付事实，检查器误杀不再自动降级体验。
- 原始模型问题仍可被量化、比较和持续优化，但不会与用户安全结果混为一谈。
- 协议升级为 0.8，Prompt 装配升级为 `pilot-runtime-prompt-v0.8`；0.7 artifact 保留为历史证据，不改写也不能复用为 0.8 完整结果。
- 检查器稳定后，在同一冻结 SHA 上先用 DeepSeek V4 Pro 连跑三批；付费执行需单独授权。
- 随后可用完全相同的动作计划、温度、样本和评测器与已支持的 Anthropic 路径盲对照。只有最终交付不下降且兜底明显减少，才考虑路由或默认模型变更。
- 本轮不微调。至少积累 200 条人工确认的“原始失败 → 可接受修复”样本并冻结评测标准后，再单独评估微调。
