# 在生成前编译本轮语义控制，并以同一计划验证交付

## Context

协议 0.6 的 DeepSeek V4 Pro 样本仍为自动人物 0/4、人工人物 0/4、人工关系 0/4。模型减少了冗余和括号动作，但继续遗漏现金约束、扩写修复历史、重开用户已经结束的决定，并在 R2 中先说“不需要选择题”再给新的二选一。

当前链路能选择带来源的关系证据，也能在总体 Judge 前运行部分语义阶段门，但关系证据进入生成时仍主要是自然语言。关系事件没有统一编译成当轮动作效果，关键语义失败也多在成文后评测，不能阻止同一草稿交付。自动 Judge 因此仍可能把换一种问句解释成关系行为变化。

ADR-0013 已证明“已确认边界 → 窄回应合同 → 缓冲输出 → 硬门 → 有界重写”对决定权边界有效。本决定把该闭环提升为共享的语义控制层，同时保持动作集合窄且可解释。

## Decision

- Engine 在自然语言生成前依次建立三个结构化对象：
  - `TurnFrame`：当前用户消息中的已确认事实、明确决定、现实约束、请求模式、必须处理项和原文证据；
  - `RelationshipEffect`：关系事件投影出的 active 动作效果、来源事件、持续条件、禁止动作和必须动作；
  - `SemanticTurnActPlan`：按固定优先级合并前两者后形成的唯一动作裁决。
- 固定优先级为：安全 > 用户当前明确边界 > active relationship effect > 当前现实约束与必须处理项 > 人物表达风格。人物核心只能决定如何表达，不能覆盖前四层的动作许可。
- `crisis/blocked` 仍由 L3 Safety 在进入人物生成前旁路；进入生成的 `normal/sensitive` 会写入同一 plan。RoomController 继续只裁决“谁说、说多长、何时停止”，`SemanticTurnActPlan` 是每个已选中发言者唯一的内容动作裁决，两者不争夺同一职责。
- 关系事件日志继续是“发生过什么”的可追溯真相源；`RelationshipEffect` 是可重建的行为投影，不创建第二套无来源关系事实。边界修订、遗忘、关闭记忆和修复接受必须使相应 effect 失效。
- 首版动作集合只覆盖高影响且可验证的行为：承接、反映、开放问题、方向性问题、二选一、菜单、建议、重开决定、共同历史声称、现实责任分配、动机辩护和停止介入。它不把自然表达、幽默或人物判断写成规则树。
- 未修复的“只想被听见却仍被安排下一步”R2 采用严格默认：建议、菜单、二选一、方向性问题和重开决定均禁止；允许承接、陪伴和非问句式 opt-in。用户当前明确请求分析或建议，或对应修复被接受后，才解除相应临时收紧。
- 当前消息明确要求“只听、不建议/分析”时，即使没有关系记忆，也直接编译为 listen 模式，优先于人物介入冲动。
- 当前消息包含“先听，等我说完再分析/建议”时，`TurnFrame` 必须区分当前 listen 与 deferred mode。deferred 请求写入 `RoomState.pendingUserRequest`，中间倾诉轮继续保持 listen；用户明确说完、重新直接请求或撤销后消费并清除，不能把跨回合意图丢在一次临时 Prompt 中。
- 生成 Prompt 只接收相关 `TurnFrame` 投影、active effects 和已批准 plan，不把三个对象当作新的完整人物卡，也不向用户朗读内部字段。
- 最终文本以同一 plan 验证实际动作。失败返回结构化 `code / evidenceSpan / effectId / repairInstruction`，进入有预算的 `transform`；仍失败则安全降级或停止，不能进入总体 Judge。
- 所有人物最终文本均在验证前缓冲，不向客户端泄露未通过草稿。原因是“无来源历史声称”等违规无法在生成前可靠预测；只有部分轮次缓冲会让普通轮先交付后校验。
- 生产与评测必须复用同一编译和验证接口。评测可以增加金标准与独立 Judge，但不得重新实现一套关系动作语义。
- 本决定将 ADR-0008 的 Branch 从 `observe_only` 迁移为生产 `active_projection`：Turn 预处理在 100ms 预算内读取完整 Branch 并投影到 Engine 的 `RelationshipPromptContext`；没有 Branch 记录时继续使用 confirmed Memory 回退，但读取超时或 Branch 解析失败必须在人物生成前明确失败。迁移为正式裁决来源后，不能再沿用影子阶段的 fail-open，否则已知 R2 effect 会被静默当成不存在。
- 生产 Prompt 版本升级为 `web-mvp-v8`；pilot Prompt 装配版本升级为 `pilot-runtime-prompt-v0.6`，旧产物不得复用为当前结果。

## Initial deterministic scope

首版先冻结并覆盖以下已观察反例：

1. R2 未修复只听边界下的二选一；
2. 离职场景遗漏现金约束；
3. 项目明确结束后重新打开可能性或复述成二选一；
4. 修复回复虚构过去具体原话；
5. 人物或未确认主体被写成现实维护负责人；
6. 当前轮明确只听时仍给建议；
7. 未修复 R2 下，用户当轮明确要求分析/建议却仍被旧限制永久压住；
8. 必须承接只存在于 Prompt 元数据而没有交付验证；
9. 普通轮虚构历史先通过 token stream 泄露、再被最终校验发现。
10. “不要建议，但帮我分析”被误判为只听，以及“我不知道该怎么办”被误判为明确请求建议；
11. 裸“我明白”绕过必须承接检查；
12. Branch 大于五十条证据时 active 边界被 Prompt 选择上限提前截掉。
13. “先听，等我说完再建议”只在当前临时对象存在，下一轮丢失或把 advice 压成 analyze；
14. RelationshipBranch 超时先于危机分流，导致安全旁路被通用 503 覆盖。

当前实现使用用户原文、已确认回应合同和结构化关系上下文进行确定性编译，不因此宣称任意自然语言都能靠正则完整理解。未来若引入结构化 controller 提取 `TurnFrame`，它必须返回原文证据；代码仍拥有最终关系 effect 合并和动作权限裁决权。

## Consequences

- 关键语义从“Prompt 建议和事后报告”变成“生成前计划与交付前验证”，模型升级只影响自然表达和剩余歧义，不再承担全部边界治理。
- 人物文本会从逐 token 展示改为通过交付门后整段发送，并可能增加一次 transform 延迟；这是避免违规草稿已经送达的有意权衡。房间动作和 lifecycle 事件仍可实时发送。
- 动作分类器必须保持窄、可解释并由真实反例驱动。新增规则需要对应冻结样本，不能因为某个理想答案而扩成通用话术模板。
- 关系生命周期成为产品语义的一部分；修复接受、边界修订和用户当轮新要求必须有明确覆盖关系。
- 当前生产自动写入仍只覆盖用户确认的 Memory 投影；普通对话中的 `meaningful_disagreement / repair_* / shared_success` 需要独立的可审计采集与确认设计，不能用无来源模型推断直接落库。
- 首版把 schema、窄规则编译、Policy、renderer 与 validator 放在同一模块便于冻结语义。样本稳定后应按这些职责拆成深模块，但必须保持一个公开 compiler seam 和一个最终 delivery-validator seam。
