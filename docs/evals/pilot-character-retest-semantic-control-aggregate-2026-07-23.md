## 仍未通过的部分

### 1. R1 事件效果连续失败

三批关系 12 个角色批次组合没有一个完整通过：

- `success-1` 经常只被复述成“上次拆过”，却没有产生只能由该共同经历解释的本轮动作。
- `context-1` 经常只让语气更直接，陌生人也可能说出相同回复。
- 周禾等人物会把“共同拆成可逆小实验”扩写成用户当时的心态、表现或结果，超出事件来源。

R1 的下一步不是添加更多关系台词，而是把事件编译为最小动作效果，例如“可直接复用已经共同验证的方法，但不替用户宣告许可或过去心态”。

### 2. 修复场景仍被写成问题或菜单

第三批林衡、夏栩、周禾都在承认越界后问“你想让我怎么处理”，再给出听 / 不聊 / 重谈等选项。它看似归还选择权，实际又要求用户处理修复流程，符合首位用户此前指出的工具化与菜单感。

通过方向应更简单：人物自己停止越界，把以后是否继续交给用户主动发起，而不是当场要求选择。例如只执行“我先停在这里。你需要我听的时候，我就听。”

### 3. C8 仍有采样波动

第三批林衡、夏栩、周禾都接受项目结束并处理了“没能力”的自我判决；许野又问“分得清腻了和干不了吗”，重新做成二选一。C8 已明显改善，但尚未跨人物稳定。

## 本轮发现并修复的评测器错误

第二批四个人都出现自然倾听却被硬门拒绝。根因有两项：

1. `ADVICE_ACT` 只要看到“建议”二字就判定建议，把“我不给建议”错误识别为真实建议。
2. `ACKNOWLEDGEMENT_ACT` 只识别少量固定句式，无法识别“我在这儿听”“就在这儿听着”“我听到了”“我不插嘴”。

本轮增加否定建议剥离与自然倾听承接识别，并补五类回归：

- 四条真实自然倾听句必须通过；
- `我不给建议，但你可以先把事情列出来再决定`仍必须因真实建议失败。

修复后全量测试为 215 项中 214 通过、0 失败、1 项 PostgreSQL 集成跳过；第三批四个人 C2 全部通过。

仍需记录而非立即扩大修复的评测口径问题：

- 机械历史门会把输入明确提供的`你昨天……`也当成无来源历史；
- Repair History Judge 会把明显的当前/未来承诺错判为不具备未来时态；
- “越过了你画的线”不一定被 acknowledgement 正则识别；
- 夏栩第一批 C8 被窄语义门放过、被总体 Judge 正确拦住。

这些问题应逐一用最小反例修，不应放宽整类历史或修复门。
