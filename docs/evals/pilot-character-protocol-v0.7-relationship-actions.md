# 首批人物评测协议 v0.7：关系动作与反事实房间

> 协议版本：`pilot-character-scenarios-v0.7`  
> Prompt 组装版本：`pilot-runtime-prompt-v0.7`  
> 房间协议版本：`pilot-room-participation-v0.2`
> 架构决策：[ADR-0017](../adr/0017-compile-positive-relationship-moves-and-counterfactual-room-cases.md)

## 1. 本轮目的

v0.7 不继续扩写人物卡，而是验证关系事实能否被编译成可观察的本轮动作，并校准四类会误杀正确回复的机械门。它同时把单一房间题改为反事实场景集，验证沉默、点名、澄清和分工，而不只验证多人是否能依次发言。

## 2. 边界修复动作

当用户指出人物此前越过“只想被听见”的边界时，本轮编译为独立 `boundary_repair`：

- 明确承认具体越界；
- 人物主动停止介入；
- 禁止建议、追问、二选一、回应方式菜单、解释好意和重开话题；
- 用户无需当场选择修复方式，之后是否重开由用户主动发起。

模型重试耗尽后，生产与评测共用的语义降级为：

> 对，是我越过了你只想被听见的边界。那我先停，不再替你往下安排。

普通倾听降级为：

> 嗯，我听着。

## 3. R1 关系动作

`RelationshipContextEvidence` 从既有事件日志投影可选 `sourceEventType`，不改变持久化 Schema。每轮最多编译一个 `relationshipMove`：

- `honor_stated_preference`：在 support、conflict、ordinary 中优先落实已确认偏好；
- `reuse_verified_method`：在 decision 中优先复用共同成功的方法。

repair、room、listen 和 explicit_end 不启用正向关系动作。active boundary 或 unresolved tension 始终覆盖正向动作。

动作必须在回复中造成可观察差异，但不得朗读关系事件、断言“你以前就是这样”或扩写共同历史。评测夹具 `context-1` 的事件类型为 `preference_stated`。

首版只把可编译、可验证的回应偏好落实为硬动作：诚实但不过度笃定、结论先行、简短回复、最多一个问题、不主动建议和例子先行。偏好明确写有“讨论/聊到 X 时”等适用范围时，当前用户消息必须命中 X 才可编译；未声明范围的回应方式偏好按当前 focus 适用。未知偏好仍可进入关系上下文，但在有明确 observable cue 前不伪装成已经机械保证。R1 分别用 support 反事实验证 `context-1`，再用 decision 反事实验证 `success-1`；每轮仍只选一个动作。

## 4. 交付门与评测口径

- 菜单检测覆盖问句和无问号菜单，包括“继续听还是……”“听 / 不聊 / 换个方式”。
- acknowledgement 接受“越过你画的线”“踩过边界”等自然表达。
- 历史机械门以当前用户消息和选中关系证据为允许来源；有来源的“昨天/上次”通过，无来源习惯性断言继续失败。
- 修复动作接受“我准备”“我会”“我先停”“不再”“接下来”等当前或未来承诺，但过去声称不能伪装成未来动作。
- C8 同时要求接受项目结束，并处理“项目结束 → 我没能力”的自我判决；任一缺失都失败，固定二分仍失败。

每次生成同时保存：

- `modelScoreable`：原始模型在重试后的能力结果；
- `deliverySource`：最终来自模型或 `semantic_fallback`；
- `fallbackUsed`：是否使用语义降级。

最终交付通过不能覆盖原始模型持续失败。

## 5. 反事实房间场景

房间不设全局发言顺序。每个 case 独立声明允许的停止原因、首位约束、必要人物和责任边界：

1. `owner-gap-regression`：维护负责人和停止条件缺失；
2. `all-pass`：全员私下 pass，公开发言为零；
3. `named-agent-first`：用户点名周禾，周禾必须先说；
4. `needs-user-input`：信息不足，只产生一个澄清问题，并以 `needs_user_input` 停止；
5. `all-four-required`：四人承担明确且不重复的观察任务，四人都发言。

参与意向新增 `ask_user`。一旦执行，房间立即等待用户，不继续轮答。

## 6. 冻结复测门

代码冻结后，同一提交、模型与运行签名连续执行三批：

- 边界修复最终交付每批 4/4，且无问题、菜单、建议和动机解释；
- 原始模型边界修复每批至少 3/4；
- R1 逐事件使用、相对 R0 行为差异和事件蕴含每批 4/4；
- R2 停止介入每批 4/4；
- C8 每批 4/4；
- 五个房间 case 全部通过；
- 无来源历史和字面语气水印为零。

每批保存独立时间戳 artifact、提交 SHA 和运行签名；运行前检查引擎、评测与协议源文件相对 HEAD 无未提交改动（允许范围外 UI 工作树继续存在）。room-only 复用也必须匹配同一提交，并从逐条回复重新计算修复双层门，不信任已存汇总值。最终另写三批聚合报告。自动评测只证明组件协议是否稳定，不代表真实用户留存、满意度或人物定位已经验证。
