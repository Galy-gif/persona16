# 文档 Agent 约定

本文件适用于 `docs/**`，并继承仓库根 `AGENTS.md`。

## 真相源与结构

- `docs/PRD.md` 是当前产品结论的真相源，根 `CONTEXT.md` 是领域语言真相源，`docs/adr/` 记录已接受的系统决策。
- 使用 `CONTEXT.md` 中的规范术语，避免把正典人物写成 MBTI 角色、把关系状态写成好感度，或把形成性证据写成已验证成效。
- 新增重要架构决策时创建下一个顺序 ADR，并写清上下文、决策、后果与替代方案；不要静默改写已有决策的历史含义。
- 新增长期文档时更新 `docs/README.md` 的导航。临时日志、下载物、构建物和一次性草稿不要进入文档树。

## 证据规则

- 明确区分已实现、已自动测试、已真实运行、已人工验证和待验证，不能用其中一种代替另一种。
- 评测记录必须注明日期、代码 SHA、协议、模型、语料/样本和限制；研究资料注明来源与访问日期。
- 不记录密钥、token、个人隐私、完整原始对话或未经脱敏的生产数据。
- 文档描述代码行为时检查当前实现和测试，避免只根据旧文档推断。

## 验证

- 检查内部相对链接、文件名、命令和术语是否与当前仓库一致。
- 涉及行为或发布状态的文档更新，应同时给出对应代码/测试/运行证据。
- 完成后运行 `git diff --check`；若文档变更伴随代码变更，执行对应模块的验证命令。
